0핵심 요약

PR #1의 핵심은 두 가지 질문에 답하는 것이다.

1) 전방 crop LiDAR에서 관측 불가능(unknown) 영역을 어떤 기준으로 판단하는가
2) FIRI가 만든 local corridor가 그 unknown 방향으로 확장되지 않도록 어떻게 제한하는가

1미지의 공간을 판단하는 기준

1.1 Crop LiDAR에서 unknown 방향이 생기는 이유

Poongsan garage simulation은 다음과 같은 crop LiDAR 조건을 쓴다. yaw가 360°가 아니므로 좌우 FOV 경계가 생기고, 그 경계 바깥은 현재 센서가 직접 보지 못하는 방향이 된다.

lidar_perception/is_360lidar: false
lidar_perception/yaw_fov:  120.0
lidar_perception/fov_up:    15.0
lidar_perception/fov_down: -15.0
lidar_perception/lidar_pitch: 0.0
기존 FIRI의 위험
FIRI corridor는 obstacle point가 없는 공간으로 polytope를 키운다. FOV 바깥쪽은 실제로는 unknown이지만 point obstacle도 없기 때문에, FIRI가 그 방향을 "장애물이 없는 공간"처럼 취급하여 corridor를 확장할 수 있다.

1.2 DENSE cell의 의미와 정의

이 문서에서 말하는 DENSE cell은 단순히 "장애물이 있는 cell"을 뜻하지 않는다. PR #1의 gate에서 DENSE는 frontier_manager의 label map에서 이미 관측된 것으로 분류된 cell을 의미한다.

즉 DENSE는 local planner가 "이 방향에는 이미 센서 관측 정보가 이어지고 있다"고 볼 수 있는 근거로 사용된다. 그래서 FOV face 바깥쪽에 DENSE가 있으면, 그 face 바깥이 무조건 unknown이라고 단정하지 않는다. 

frontier_manager label map 기준:

DENSE cell
  = 이미 충분히 관측된 cell
  = gap / FOV edge가 아니고, 관측 거리·방향 조건을 만족한 cell
  = 또는 가까운 거리에서 강하게 신뢰 가능한 관측 cell

UNKNOWN과의 차이:
  UNKNOWN = label map에서 아직 관측 상태가 확정되지 않은 cell
  DENSE   = 이미 관측된 공간이 이어진다는 증거로 쓸 수 있는 cell
왜 DENSE outside가 있으면 자르지 않는가

FOV face 바깥쪽에 DENSE cell이 있다는 것은, 그 face 너머에도 이미 관측된 cell이 존재한다는 뜻이다. 이 경우 해당 face를 관측 경계로 확정하고 잘라버리면, 실제로는 관측되어 지나갈 수 있는 공간까지 막을 수 있다.

반대로 face 바깥쪽에 DENSE cell이 없으면, 그 바깥 방향에 관측이 이어진다는 증거가 없다. 그래서 PR #1은 그 face를 보수적으로 관측 경계로 보고 corridor clipping에 사용한다.

1.3 fov_edge_cells_의 의미

fov_edge_cells_는 unknown 공간 전체의 voxel map이 아니다. 이것은 현재 LiDAR depth image와 frontier classification을 통해 얻은 FOV 경계 위의 frontier cell 집합이다.

local planner는 이 cell들을 보고 "어떤 FOV face가 실제 관측 경계 후보인가"를 판단한다. 즉 fov_edge_cells_는 corridor를 자를 face를 고르는 근거이지, unknown 영역 전체를 표현하는 map이 아니다. 

fov_edge_cells_
  = cropped LiDAR FOV 경계에 놓인 frontier cell들
  = active clipping face 후보를 찾기 위한 evidence
  ≠ 전체 unknown voxel map

1.4 DENSE outside gate

PR #1은 fov_edge_cells_가 있는 face를 무조건 자르지 않는다. 해당 face 바깥쪽에 DENSE cell이 있는지 한 번 더 확인한다. 

FOV edge frontier가 존재하고,
그 face 바깥쪽에 이미 관측된 DENSE cell이 없으면,
   → 그 face 바깥쪽을 현재 관측 불가능 방향으로 보고 corridor를 자른다.

FOV edge frontier가 존재하더라도,
그 face 바깥쪽에 DENSE cell이 있으면,
   → 이미 관측이 이어지는 방향일 수 있으므로 자르지 않는다.

1.5 가장 중요한 오해 방지

여기까지의 내용을 정리하면, PR #1은 unknown 공간을 처리하지만 그 방식은 voxel-level raycast 검증이 아니다. PR #1은 FOV boundary 기반의 기하학적 corridor 제한이다.

가장 중요한 오해 방지
PR #1은 corridor 내부 모든 점을 raycast map으로 샘플링해서 unknown 여부를 검사하는 방식이 아니다. 대신 관측 가능한 FOV 경계를 corridor의 기하학적 절단면(half-plane)으로 사용한다. 
LiDAR FOV 경계에서 생기는 frontier / FOV-edge cell을 관측 경계로 사용
        │
        ▼
그 경계에 대응하는 FOV cone face를 half-plane으로 구성
        │
        ▼
FIRI corridor hPolys에 해당 half-plane을 추가
        │
        ▼
corridor가 관측 FOV 바깥 unknown 방향으로 커지지 못하게 제한
하지 않는 것:
  corridor 내부 전체 voxel sample → raycast observed-free 검사 → unknown이면 제거

하는 것:
  FOV edge frontier + DENSE outside gate → active FOV face 선택 → hPoly에 half-plane 추가

1.6 Figure 1: Unknown 판단 기준 — FOV Edge Frontier와 DENSE Cell Gate

Figure 1은 1.1~1.4에서 설명한 판단 기준을 한 장으로 요약한다. 특히 DENSE cell이 왜 gate 역할을 하는지, 그리고 어떤 경우에 FOV face가 active clipping face가 되는지를 시각적으로 보여준다.

DENSE cell의 의미와 gate 직관

Figure 1에서 말하는 DENSE cell은 단순히 "장애물 cell"이라는 뜻이 아니다. PR #1 문맥에서는 frontier_manager의 label map에서 이미 관측된 것으로 분류된 cell, 또는 해당 방향에 관측 정보가 이어지고 있다는 증거로 사용된다.

따라서 FOV face 위에 fov_edge_cells_가 있는데, 그 face 바깥쪽 이웃에 DENSE cell이 없다면, planner 입장에서는 그 바깥 방향에 "이미 관측된 공간이 계속된다"는 증거가 없다. 이때 PR #1은 그 face를 현재 센서의 관측 경계로 보고, corridor가 그 바깥 unknown 방향으로 커지지 못하게 자른다.

반대로 face 바깥쪽에 DENSE cell이 있다면, 그 방향은 이미 관측된 cell들이 이어져 있는 방향일 수 있다. 이 경우 face를 무조건 절단면으로 쓰면, 실제로 관측되어 지나갈 수 있는 통로까지 잘라버릴 수 있다. 그래서 PR #1은 그 face를 clipping face로 쓰지 않고 비활성화한다. 

DENSE outside 없음
  = face 바깥에 이미 관측된 공간이 이어진다는 증거가 없음
  → 보수적으로 관측 경계로 보고 corridor를 자름

DENSE outside 있음
  = face 바깥에도 이미 관측된 cell이 존재함
  → 관측이 이어지는 방향일 수 있으므로 corridor를 자르지 않음
Figure 1을 읽는 법

이 그림에서 가장 중요한 점은 PR #1이 공간 전체를 voxel 단위로 raycast해서 unknown map을 완성하는 방식이 아니라는 것이다. 대신 현재 cropped LiDAR가 만든 depth image에서 fov_edge_cells_를 찾고, 그 cell들이 놓인 FOV face를 "관측 경계 후보"로 본다.

왼쪽 face처럼 fov_edge_cells_는 있는데 그 face 바깥쪽 이웃에 DENSE cell이 없으면, PR #1은 그 바깥을 아직 관측이 이어지지 않은 방향으로 해석한다. 따라서 이 face는 active clipping face가 되고, FIRI corridor가 그 바깥 unknown 방향으로 커지지 못하도록 half-plane constraint로 추가된다.

반대로 오른쪽 face처럼 face 바깥쪽에 DENSE cell이 있으면, 그 방향은 이미 관측된 공간이 이어지는 방향일 수 있다. 이때 face를 무조건 절단면으로 쓰면 실제로 지나갈 수 있는 통로까지 막아버릴 수 있으므로, PR #1은 그 face를 비활성화하고 corridor를 자르지 않는다. 

FOV-edge frontier exists?
        │
        ├─ no
        │    → 이 face는 관측 경계 후보가 아니므로 clipping에 사용하지 않음
        │
        └─ yes
             │
             ├─ outside neighbor has DENSE cell
             │    → 이미 관측이 이어지는 방향일 수 있으므로 clipping하지 않음
             │
             └─ outside neighbor has no DENSE cell
                  → 이 face 바깥을 관측 불가능 방향으로 보고 corridor clipping에 사용

2미지 공간으로 corridor가 들어가지 않게 하는 방법

기존 local planner는 FIRI / convexCover로 guide path 주변에 convex safe corridor(hPolys)를 만든다. PR #1은 raw hPolys를 바로 MINCO에 넣지 않고, 관측 FOV cone으로 한 번 더 제한한다.

guide path → FIRI/convexCover → raw hPolys
                                     │
                                     ▼  observed FOV cone clipping  ← PR #1
                                clipped hPolys
                                     │
                                     ▼
                               MINCO / GCOPTER

2.1 FOV cone face 구성

전방 LiDAR FOV는 현재 드론 위치를 꼭짓점으로 하는 cone이다. 3D에서는 대략 네 개의 face(left/right yaw, upper/lower pitch)가 있고, 각 face는 half-plane으로 표현된다.

n·x + d ≤ 0 : FOV cone 안쪽
n·x + d > 0 : FOV cone 바깥쪽

2.2 active face만 사용 (두 조건)

모든 face를 무조건 추가하면 이미 관측된 공간까지 잘려 경로가 과도하게 보수적이 된다. 그래서 다음 두 조건을 만족하는 face만 hPoly에 추가한다.

조건 1: 해당 face 위에 fov_edge_cells_가 있음
조건 2: 해당 face 바깥쪽에 DENSE cell이 없음
   → 이 face는 실제 관측 경계이고, 바깥은 관측되지 않은 방향

2.3 half-plane 추가 과정 & feasibility 보장

FIRI가 만든 각 hPoly에 active FOV face를 추가하되, 첫 번째 P0 seed box는 예외로 둔다. 각 face 추가 후 corridor가 완전히 비지 않는지 확인한다.

hPolys[0]     = P0 seed box, 유지 (시작점 안정성)
hPolys[1..N]  = active FOV face를 추가해서 clip

face 추가 후보 hPoly 생성
   → findInterior()로 내부점 존재 확인
   → 내부점 있으면 face 추가 / 없으면 해당 cut skip  (infeasible 방지)
raw hPolys  ∩  active observed FOV cone half-planes  =  clipped hPolys
